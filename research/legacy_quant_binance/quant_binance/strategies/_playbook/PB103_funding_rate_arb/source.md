- 언어: Python 100%

## 셋업 한 줄

**다중 거래소의 USDT-perp 펀딩 비율 차이를 탐지하여, 한 쪽에서 long(낮은 펀딩) + 다른 쪽에서 short(높은 펀딩) 의 delta-neutral 포지션을 추천**하는 분석 프레임워크. 우리 환경에서는 단일 거래소(Bitget) 전용이므로 펀딩 차익 자체는 활용 어려우나, **펀딩 극단치(>+0.1% 또는 <-0.1%) 자체가 역방향 lottery short/long 시그널** 로 활용 가능.

## 우리 시스템 포팅 옵션

**옵션 A — 펀딩 데이터 추출 코드만 채택, 단일 거래소 lottery 시그널화** (권장)
- aoki-h-jp 의 Bitget 펀딩 추출 모듈 → quant_binance/data/funding.py 신규
- 룰: `if funding_8h > +0.10%: short setup arm` / `if funding_8h < -0.10%: long setup arm`
- pro: $50 lottery 컨텍스트와 정합. 양방향 gap 충족 (long+short 양쪽 시그널)
- con: 펀딩 극단치 시그널의 알파는 학술 검증 부족 — 자체 백테스트 필수

**옵션 B — 본질 셋업(거래소 간 차익) 그대로** (비추천)
- 2개 거래소 동시 운용 (예: Bitget short + Binance long)
- pro: 시장 중립 → MDD 낮음
- con: $50 자본으로 2개소 동시 운용 = 사이즈 ¼. 거래당 큰 수익(lottery) 컨텍스트와 정반대 — **사용자 자본 컨텍스트 위반**

**옵션 C — 펀딩 플립 모멘텀** (실험적)
- 펀딩이 +에서 - 로 (또는 - 에서 +로) flip 하는 시점에 역방향 진입
- pro: 시장 sentiment 전환 포착 가능
- con: 백테스트 알파 미검증. 우리 자체 검증 필요

**권장: 옵션 A.** **본질 셋업이 우리 컨텍스트와 불일치하므로, "펀딩 극단치 시그널" 만 차용**하여 단일 거래소 lottery short/long 시그널로 활용. 옵션 C 는 G 전략 검증 후 보완.

## 알려진 risk / 한계

- **본질 셋업 불일치**: 우리는 단일 거래소(Bitget). 거래소 간 차익 셋업 본질을 포기하고 부분 차용 — **신뢰도 평점 종합 3.0 경계선**
- **자동 실행 미지원**: 분석 프레임워크. 라이브 hook 우리가 작성 필요
- **펀딩 극단치 시그널 = 자체 검증 필수**: aoki-h-jp 셋업의 알파가 아님. 우리 자체 백테스트로 양수 확인 후 G 발급
- **Lottery 충족도 중간**: 펀딩 극단은 빈도 낮음 (월 5~10회 알트 perp). 진입 빈도 ≥3건/일 목표에는 보조 시그널로만 활용
- **MIT 라이선스**: 자유 ◎
