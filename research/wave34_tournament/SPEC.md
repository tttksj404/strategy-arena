# Wave-34 사전등록 — 미시도 탐색기법 통제 토너먼트 (동결: 2026-07-30)

## 요구
**"$100 고정, 하루 1회 이상 진입, 수익 최대"** — 그리고 사용자가 제시한 기법 목록(진화계산·강화학습·메타휴리스틱·베이지안 최적화·MCTS)을 참고할 것.

## 이 wave가 하나를 고르지 않고 토너먼트를 하는 이유

사용자 목록 중 **이 저장소에서 이미 소진된 것**과 **한 번도 안 해본 것**을 분리하면:

| 기법 | 상태 |
|---|---|
| 유전 알고리즘 (GA) | ✅ 완료 — wave21·23·27·28 (4회) |
| 유전 프로그래밍 (GP) | ✅ 완료 — wave24 (랜덤트리에 1/5승, "탐색 방법론 소진" 선언) |
| MAP-Elites / NSGA-II | ✅ 완료 — wave30·31·33 |
| **CMA-ES** | ❌ **미시도** |
| **입자 군집 최적화 (PSO)** | ❌ **미시도** |
| **시뮬레이티드 어닐링 (SA)** | ❌ **미시도** |
| **베이지안 최적화 (TPE)** | ❌ **미시도** |
| **몬테카를로 트리 탐색 (MCTS)** | ❌ **미시도** |
| **강화학습 (Q-learning)** | ❌ **미시도** |

**하나만 고르면 답을 알 수 없다.** 이 캠페인은 이미 두 개의 상충하는 결론을 갖고 있다:
- wave24(GP)·wave30(MAP-Elites): **탐색이 동일예산 랜덤을 못 이겼다** (각 1/5, 2/5)
- wave31·wave33: **같은 알고리즘이 랜덤을 이겼다** (각 5/5) — 바뀐 것은 목적함수뿐

즉 미해결 질문은 "어떤 기법이 좋은가"가 아니라 **"이 문제에서 기법 선택이 결과를 바꾸는가"**다. 그것은 **목적함수·예산·평가기·시드·탐색공간을 전부 고정하고 기법만 교체**해야 답할 수 있다. 그래서 이 wave는 **통제 토너먼트**다.

## 강화학습을 별도 arm으로 분리하는 이유
위 5개 메타휴리스틱은 전부 **정적 규칙의 파라미터 벡터**를 탐색한다 — wave1~33 전체가 그랬다. **강화학습만이 상태의존 정책**(같은 종목에서 시장 상태에 따라 다르게 행동)을 탐색하며, 이는 **탐색 알고리즘이 아니라 탐색 공간이 다르다.** 따라서 동일 예산 비교 대상에 넣지 않고 **별도 arm**으로 보고한다(같은 예산으로 비교하면 공간이 달라 무의미).

## 공통 고정 요소 (기법 간 차이 외 모든 것을 동결)

- **탐색공간**: `research/wave30_qd/genome30.py` 13축 유전자, 무수정.
- **엔진**: `research/wave30_qd/engine30.py` 무수정 (기본 복리 사이징 = `COMPOUNDING`).
- **자본**: 총 $100. 슬리브 비율은 유전자, 잔여는 I5 실측 수익률.
- **비용**: 테이커 0.06% + wave13 실측 슬리피지, 왕복·펀딩 모두 레버리지 증폭.
- **유니버스**: BTC/ETH/SOL 1h (데이터 제약, Binance API 451).
- **OOS 봉인**: `OOS_SPLIT = 2025-09-30`. 탐색은 IS만. 위반 시 `OOSLeakageError`.
- **예산**: **기법당 3,000 평가 × 5시드** (시드 2026341~2026345). 6기법 = **90,000 평가**.
- **평가기**: 6기법이 동일 `Evaluator` 구현·동일 메모이즈 규칙을 쓰고, **중복 유전자는 예산에서 차감되지 않는다**(캐시 히트로 몰래 추가 탐색을 사는 것을 막음).

## 연속벡터 인코딩 (동결) — 토너먼트 공정성의 핵심

CMA-ES·PSO·SA·TPE·MCTS는 실수 벡터 공간에서 작동하므로 유전자를 **`[0,1]^13`** 로 인코딩한다.
- 범주형 유전자(계열·룩백·보유·심볼집합·동시수·쿨다운·슬리브비율·숏허용·트레일링): 좌표를 균등 구간으로 나눠 인덱스로 사상.
- 연속형(entry_threshold·target_r·risk_frac): 범위 선형 사상.
- **`stop_pct`는 "가능구간 내 상대위치"로 재모수화한다.** `risk_frac`을 먼저 디코딩한 뒤 `stop_pct = min_stop(risk) + u × (max_stop(risk) − min_stop(risk))`.
  - **이것은 repair가 아니다.** 좌표의 의미 자체가 "그 risk에서 허용되는 손절폭 범위 내 위치"이므로, 디코딩된 유전자는 **정의상 항상 실행가능**하고 infeasible 영역은 애초에 표현되지 않는다. (기존 wave들의 fail-closed 원칙 — 위반 유전자를 사후에 고쳐 쓰지 않는다 — 을 유지한다.)
- 랜덤 대조군도 **동일한 인코딩에서 균등추출**한다. 그렇지 않으면 대조군이 다른 분포를 보게 되어 비교가 무효다.

## 목적함수 (동결)

```
feasible = (trades_per_active_day >= 1.0) AND survived_full_span
fitness  = log(IS 최종 총자본 / 100)  −  (feasible ? 0 : 100)
```
- **로그증가**를 쓰는 이유: 요구가 "수익 최대"이고, 로그는 CMA-ES/PSO/SA가 다루기 쉬운 스케일이며 파산($0)을 −inf로 자연히 밀어낸다(하한 클립 적용).
- **빈도·생존은 하드 페널티**(−100). 요구 조건을 못 지킨 개체가 상단을 점유하지 못하게 한다.
- `trades_per_active_day`와 `survived_full_span`의 정의는 **wave33 규약을 그대로 승계**한다(활동기간 = 첫 진입일~마지막 청산일; 사망 후 기간을 분모에 넣으면 매매속도가 왜곡되므로).

## 강화학습 arm (동결)

- **알고리즘**: tabular Q-learning (ε-greedy, 시드 5개).
- **상태**: (모멘텀 구간 3 × 변동성 구간 3 × 펀딩부호 3 × 보유상태 3) = 81 상태. 전부 **직전 봉까지의 정보만** 사용.
- **행동**: {flat, long, short} 3가지. 진입·전환 시 왕복 비용과 펀딩을 동일 비용모델로 과금.
- **보상**: 봉당 로그 자산변화.
- **레버리지**: 사전 고정 그리드 {1, 3, 5, 10, 20}x 각각 독립 학습 (레버리지를 학습시키면 비교 대상이 흐려짐).
- **학습/평가 분리**: IS에서만 학습. 학습된 Q-table을 고정한 뒤 **탐욕적 정책**으로 IS·OOS를 재생. 학습 중 OOS 접근 금지.
- 이 arm은 **승격 후보를 내지 않는다.** 목적은 "상태의존 정책이 정적 규칙보다 나은가"의 1차 관측이다.

## 게이트 (동결, 사후 조정 금지)

- **G1 기법 우열 (주 결과)**: 각 기법에 대해 "시드별 최고 적합도 > 랜덤 대조군 최고"인 시드 수를 집계. **≥4/5면 그 기법은 '랜덤 초과' 판정.** 이 게이트는 승격 조건이 아니라 **측정 대상**이다(어느 기법도 통과하지 못하는 것 자체가 결과).
- **G2 빈도·생존**: 판정 후보가 `trades_per_active_day ≥ 1.0` ∧ IS 전기간 생존.
- **G3 OOS**: 판정 후보의 **OOS 총수익 > 0** ∧ **OOS 연환산 > I5 기준선의 OOS 연환산**. 봉인해제 1회.
- **G4 파산**: 일별수익 MC 부트스트랩 1e4에서 **P(총자본 < $50) < 5%**.
- **G5 실행가능**: 전 진입 notional ≥ $5 ∧ 레버리지 ≤ 20x ∧ 손절이 청산선 안쪽 ∧ **청산 0건**.
- **G6 용량 (신설)**: **최대 진입 notional ≤ $50,000.**
  - 근거: wave30의 판정 후보는 최대 notional **$1,906,887**로 비용모델 적합 주문크기($45 Bitget 호가 워크)의 **42,375배**였고, 이것이 IS 수치를 부풀린 최대 요인이었다. 복리 목적함수는 이 함정을 다시 만든다. $50,000은 여전히 적합 크기의 1,111배 외삽이지만 BTC/ETH 퍼프 호가가 수 bp 내에 흡수하는 범위이며, **상한을 명시적으로 걸어 재발을 막는다.**

**승격 = G2~G6 전부** (G1은 측정 항목). 하나라도 미달이면 정직 기각 + 기법별 성능표 전체 공개.

## 판정 후보 선정 규칙 (동결 — 결과 확인 전)
1. 기법별로 5시드 최고 적합도의 **중앙값**을 계산한다.
2. 그 중앙값이 가장 높은 기법을 **우승 기법**으로 한다. (랜덤 대조군이 우승할 수도 있으며 그 경우 그대로 보고한다.)
3. 우승 기법의 **median-seed 개체**가 판정 후보다. **최고 시드 채택 금지.**
4. OOS 봉인해제는 이 1개에 대해 **단 한 번**. 탈락 시 다른 기법·다른 시드로 넘어가지 않는다.

## OOS 창 4번째 사용 (정직 고지)
wave31(후보 C) → wave32(L1) → wave33(빈도 후보) → wave34(이번). **같은 홀드아웃의 4번째 사용이다.**
누적 시행수 = 295,081 + 90,000 = **385,081**. 반복 개봉은 홀드아웃을 검증에서 탐색으로 전락시키므로, 이 wave에서 탈락하면 **후보 교체 없이 종료**한다.

## 사전 예상 (등록)
1. **어느 기법도 랜덤을 크게 이기지 못할 가능성이 높다.** 근거: wave24(GP 1/5)·wave30(MAP-Elites 2/5). 이 목적함수(로그증가 + 하드 페널티)는 페널티 절벽 때문에 지형이 험하다 — wave31·33이 랜덤을 이긴 이유는 목적함수가 매끄러웠기 때문이고, 이번은 그렇지 않다.
2. **G3(OOS)가 가장 위험하다.** wave30·32의 후보가 각각 OOS 연 −95.5%·−2.1%로 무너졌다.
3. **G6(용량)이 복리 목적함수를 직접 제약**하므로, 통과하는 후보는 필연적으로 수익이 낮다. 이 긴장은 의도된 것이다.
**그럼에도 값어치 있는 이유**: "기법을 바꾸면 결과가 달라지는가"는 이 캠페인 33개 wave의 누적 미해결 질문이고, 통제 실험 없이는 다음에 또 같은 요청이 반복된다. 6기법 성능표가 나오면 **"더 좋은 알고리즘을 쓰면 된다"는 가설을 정량적으로 닫거나 열 수 있다.** 기각도 결과다.
