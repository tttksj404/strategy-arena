# Wave-34 리포트 — 미시도 탐색기법 통제 토너먼트 (CMA-ES·PSO·SA·베이지안·MCTS·강화학습)

실행 2026-07-30 · 사전등록 `research/wave34_tournament/SPEC.md`(실행 전 동결) · 평가 90,000회 + RL 25회 학습 · 판정 **기각 (G3·G4 FAIL)**

---

## 한 줄 결론

**탐색 기법을 바꾸면 결과가 달라진다는 것이 처음으로 확인됐다** — Simulated Annealing이 동일예산 랜덤 대조군을 **5시드 전승**으로 이겼다(중앙값 +1.815 vs +0.517). 그러나 **더 좋은 탐색이 더 좋은 전략을 주지는 않았다**: SA가 찾은 최고 개체는 IS 연 +34.0%인데 **OOS 연 −65.7%**, 파산확률 16.3%로 기각됐다. 그리고 **강화학습은 5레버리지 × 5시드 전부에서 "관망"을 학습**했다 — 상태의존 정책을 자유롭게 학습시켜도 "하루 1회 이상 진입"은 −EV라는 결론에 기계가 독립적으로 도달했다.

## 1. 왜 하나를 고르지 않고 토너먼트를 했나

사용자 목록 중 **이미 소진된 것**과 **미시도**를 분리하면: GA(wave21·23·27·28)·GP(wave24)·MAP-Elites/NSGA-II(wave30·31·33)는 완료, **CMA-ES·PSO·SA·베이지안(TPE)·MCTS·강화학습은 전무**였다.

그리고 이 캠페인은 상충하는 두 결론을 갖고 있었다:
- wave24(GP 1/5)·wave30(MAP-Elites 2/5): **탐색이 랜덤을 못 이겼다**
- wave31·wave33 (5/5): **같은 알고리즘이 랜덤을 이겼다** — 바뀐 것은 목적함수뿐

즉 미해결 질문은 "어떤 기법이 좋은가"가 아니라 **"기법 선택이 결과를 바꾸는가"**였고, 그건 목적함수·예산·평가기·시드·탐색공간을 전부 고정하고 **기법만 교체**해야 답할 수 있다.

**공정성 장치**: 6기법 전부가 동일한 `[0,1]^13` 인코딩에서 표본을 뽑는다(랜덤 대조군 포함 — 대조군을 다른 분포에서 뽑으면 비교가 무효). `stop_pct`는 **가능구간 내 상대위치로 재모수화**해 디코딩된 유전자가 정의상 항상 실행가능하게 했다 — 이는 repair가 아니며, 기존 wave들의 fail-closed 원칙(위반 유전자를 사후에 고쳐 쓰지 않음)을 유지한다.

## 2. 🏁 토너먼트 결과 (적합도 = log(IS 최종/100), 제약 위반 −100)

| 기법 | 중앙값 | 시드별 최고(제약충족) | 제약충족 개체수 | 랜덤 대비 승 | 평균 소요 |
|---|---|---|---|---|---|
| **Simulated Annealing** | **+1.815** | +0.834 / +2.129 / +1.815 / +2.352 / +1.169 | 1138·1467·1485·1268·1327 | **5/5 → 랜덤 초과** | 13.3분 |
| PSO | +1.319 | +3.015 / — / — / +1.319 / +4.948 | 1943·0·0·2354·2201 | 3/5 미달 | 7.6분 |
| **랜덤 대조군** | +0.517 | +0.517 / +0.514 / +0.537 / +0.824 / +0.512 | 79·75·67·61·69 | — | 3.3분 |
| TPE (베이지안) | +0.498 | +0.510 / +0.498 / −0.024 / −1.625 / +0.512 | 2·4·5·1·7 | **0/5** 미달 | 2.8분 |
| CMA-ES | 산출 실패 | — / — / +0.312 / — / +0.715 | 0·0·1·0·2688 | 1/5 미달 | 2.7분 |
| MCTS | 산출 실패 | — / — / +0.561 / — / — | 0·0·1821·0·0 | 1/5 미달 | 2.7분 |

### 이 표에서 실제로 배운 것
1. **담금질 기법만 안정적으로 이겼다(5/5).** 이유는 그 알고리즘의 성질과 목적함수 지형이 맞았기 때문이다 — 이 목적함수는 제약 위반에 −100 절벽이 있어 지형이 험한데, SA는 **초기에 나쁜 해도 확률적으로 수용**하므로 절벽을 넘어 제약 충족 영역으로 들어간다. 그리고 온도를 버닌 표본의 적합도 분산으로 자동 설정한 것이 결정적이었다(고정 온도면 전부 수용하거나 전부 거부한다).
2. **CMA-ES와 MCTS는 5시드 중 3~4개에서 제약 충족 개체를 아예 못 찾았다.** 둘 다 초기 위치/분할에서 시작해 국소적으로 조여 들어가는데, 제약 충족 영역이 좁고 페널티 절벽에 둘러싸여 있어 갇힌다. **강력한 알고리즘이 험한 지형에서 랜덤보다 나쁠 수 있다**는 실증이다.
3. **실무에서 가장 널리 쓰이는 TPE(Optuna/Hyperopt 계열)가 0/5로 랜덤보다 나빴다.** 초기 무작위 표본(예산의 5%)이 제약 영역을 거의 못 잡아(제약충족 1~7개), 대리모델의 '좋은 분포' l(x)가 잘못된 곳에 형성되고 이후 예산 전부를 그 근처에서 소모했다. **베이지안 최적화는 초기 표본이 유망 영역을 담지 못하면 그 실패를 증폭한다.**
4. **비용의 비대칭성(관찰)**: 기법별 소요시간이 2.7~13.3분으로 5배 차이 났는데, 이는 트리·행렬 연산 오버헤드가 아니라 **제약을 충족하는 유전자가 훨씬 비싸기 때문**이다(오래 생존 → 수천 거래 → 시뮬레이션 비용 증가). 즉 잘 찾는 기법이 더 오래 걸린다. 예산은 사전등록대로 **평가 횟수**로 통제했으므로 이 차이는 공정성 문제가 아니다.

## 4. 🤖 강화학습 arm — 가장 결정적인 결과

81상태(모멘텀3 × 변동성3 × 펀딩부호3 × 보유상태3) × 3행동(관망/롱/숏), 5레버리지 × 5시드 = 25회 학습.

| 레버리지 | IS 배수(중앙) | OOS 배수(중앙) | **IS 진입/일** | 청산 |
|---|---|---|---|---|
| 1x | 1.000 | 1.000 | **0.00** | 0 |
| 3x | 1.000 | 1.000 | **0.00** | 0 |
| 5x | 1.000 | 1.000 | **0.00** | 0 |
| 10x | 1.000 | 1.000 | **0.00** | 0 |
| 20x | 1.000 | 1.000 | **0.00** | 0 |

**전부 "관망"을 학습했다.** 이것이 argmax 기본값 아티팩트가 아님을 세 가지로 확인했다:
1. **학습은 실제로 일어났다** — 업데이트 1,184,176건, Q 비영 항목 162/243, |Q| 최대 0.130.
2. **Q값의 순서가 경제적으로 일관된다** — Q(flat) −0.00034 > Q(long) −0.00596 > Q(short) −0.00981. 숏이 가장 나쁜 것은 펀딩을 지불하는 쪽이 많았다는 뜻이다.
3. **반사실 검정이 결정적** — flat 행동을 금지해 강제로 매매시키면 IS 배수 **0.0000**(37,344진입, 전멸).

**해석**: 정적 룰이 아니라 상태의존 정책을 학습할 자유를 줬는데도, 에이전트는 **"이 비용 구조에서 최선의 행동은 진입하지 않는 것"**이라는 결론에 도달했다. 이는 사용자 요구("하루 1회 이상 진입")와 정면으로 충돌하며, wave33의 빈도 프론티어(빈도를 올리면 진입당 기대값의 부호가 바뀜)를 **완전히 다른 방법론으로 재확인**한다.

## 5. 한계

1. **OOS 창 4번째 사용** (wave31 C → wave32 L1 → wave33 빈도후보 → wave34). 누적 시행수 **385,081**. 사전등록대로 탈락 후 다른 기법·시드로 넘어가지 않았다.
2. **유니버스 3종목** — 이 wave 시점의 데이터 제약. **wave35에서 42종목으로 해소했다**(아래).
3. **RL은 tabular Q-learning**이다. DQN/PPO/SAC라면 다른 답이 나올 수 있으나, SPEC이 기록한 이유는 편의가 아니라 증거의 성질이다 — 81상태 테이블은 사람이 읽고 감사할 수 있어서 양성 결과가 경제적 의미를 담았는지 확인 가능하다. **tabular이 엣지를 못 찾은 상태에서 더 깊은 모델이 찾는다면 그건 더 의심스러운 결과이지 더 설득력 있는 결과가 아니다.**
4. **기법별 하이퍼파라미터는 교과서 기본값**으로 고정했다(SA 온도만 데이터 기반 자동설정). 각 기법을 개별 튜닝하면 순위가 바뀔 수 있다 — 다만 그 튜닝 자체가 또 하나의 탐색이 되어 다중검정을 늘린다.
