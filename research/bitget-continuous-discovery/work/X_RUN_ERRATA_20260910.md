# 최초 사전등록과 실제 실행의 차이·교정 이력

원래 `X_DISCOVERY_PREREG_20260910.md`와 최초 보고서는 결과 확인 뒤 덮어쓰지 않는다.

1. 사전등록의 ‘기존 Donchian 대조군’과 ‘고정 총노출 5배’는 실제 v2 구현과 다르다. 구현은 전체 알트 13개 분모이므로 ‘전체 종목 분모 Donchian 변형에 ×1/2/5 배율 적용’이 정확하다. 원본 active-N 신호는 별도 `X_CONTROL_PREREG_20260910.md`의 9개 진단으로 실행했다. 두 실험의 후보/PBO를 합치지 않는다.
2. 사전등록의 ‘test 조회 전 잠금’은 ‘test 성과 계산 전 목록 잠금’으로 한정한다. 코드가 전체 가격 패널을 먼저 로드하지만, 검증 계산에는 test 시작 시가까지의 prefix만 전달한다. 파일 자체를 열지 않은 sealed OOS라고 주장하지 않는다. 미래 가격 변경 회귀와 독립 코드 검토에서 수익 계산 누출은 재현되지 않았다.
3. 최초 Windows 실행은 test 식별자 LF 문자열을 해시하고 CRLF 파일을 저장했다. 식별자 내용과 선택은 일치하지만 실제 파일 바이트 해시는 불일치했다. `lock_test_ids`는 UTF-8 LF 바이트를 직접 저장하고 저장 파일 바이트를 다시 읽어 SHA-256을 반환하도록 수정했다. 최초 증거를 지우지 않고 `_recheck` 폴더로 전체 재실행했다.
4. 24시간 전체 거래량이 0인 경계의 비율 1을 0으로 바꿨다. 초기 워밍업은 기존대로 비율 1을 유지한다. 245개와 9개 대조를 각각 재실행하여 결과 동일성을 검사한다. 규칙 임계값·선택 기간·우승자는 바꾸지 않는다.
5. 최신 시세 갱신기의 첫 실행은 V3 최근 캔들 API 마지막 페이지에 startTime=endTime을 보내 HTTP 400으로 중단됐다. 같은 시각의 넓은 범위 요청은 성공했고 합성 회귀로 원인을 재현했다. 요청 하한을 한 봉 앞까지 허용하고 반환값에서 실제 요청 시작 이후 완료봉만 남기는 방식으로 수정했다. 키나 비공개 API와 관련된 오류가 아니다.
6. 독립 검토에서 저장된 SETTINGS를 재사용할 때 30일 범위 검증을 건너뛰는 경계와, 개별 MANIFEST가 일부 감사 실패를 complete 판정에 반영하지 않는 경계를 발견했다. 7개 실패 회귀를 먼저 재현한 뒤 신규·재개 공통 모델 검증과 공통 완료 판정으로 수정했다. 기존 196개 그룹은 모든 감사 지표가 0이므로 원래 수집물의 판정·해시에는 변화가 없다.
7. 16쪽 기존 전략 PDF의 8쪽 설명용 경로가 표시한 장벽을 실제로 통과하지 않는 도식 오류를 발견했다. 장벽 82를 먼저 통과하고 나중에 회복하는 합성 경로로 수정하고 데이터 회귀와 렌더 확인을 수행했다. 82는 실제 Bitget 청산가가 아니다.
8. 첫 저장소 사본 테스트는 과거 전체 원시 자료를 제외한 포장 정책 때문에 잠금 일봉을 읽는 실제 데이터 테스트 2개가 실패했다(239 통과). 테스트를 생략하지 않고 1,317,753바이트의 원래 일봉 아카이브 506개 파일을 해시 보존 복사에 포함했다. 대용량 과거 intraday 전체 원시는 여전히 별도 보관이며 동일 데이터 해시가 있어야 전체 재실험을 재현할 수 있다.
