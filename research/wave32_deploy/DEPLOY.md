## 1. 결론 먼저 — 새로 도입할 것은 없다

요구는 "확실한 걸 가져와서 paper로 실험하고 오늘 당장 도입 가능하게"였다. **"확실한 것"으로 후보였던 L1은 OOS 봉인해제에서 탈락했다.**

## 3. 매일 실행 절차 (오늘부터 가능)

```bash
python research/wave32_deploy/live_signal.py --run-once
```

- 읽기 전용. Bitget **공개** 엔드포인트만 사용하고 주문·계정·출금 엔드포인트를 **참조조차 하지 않는다.**
- 출력: `research/wave32_deploy/LIVE_SIGNAL.md` (사람이 읽는 계획서) + `ledger/carry_live_ledger.jsonl` (전진검증 원장, 하루 1건 멱등)
- 결과가 `HOLD_CASH`면 **아무것도 하지 않는다.**
- 결과가 `OPEN_CARRY`면 아래 사이징대로 **손으로** 두 레그를 낸다.

### $100 사이징 (자본규약 — 변경 시 재검증 필요)

| 항목 | 값 |
|---|---|
| 총자본 | $100.00 |
| 예비금 (건드리지 않음) | $10.00 |
| 활성자본 | $90.00 |
| 현물 롱 레그 | **$45.00** |
| 퍼프 숏 레그 | **$45.00** (1x 격리) |
| gross 노출 | $90.00 = **1.00x** |
| 동시 페어 수 | **1** |
| 최소주문 충족 | $45 ≫ $5 ✅ |

주문 유형은 **지정가(메이커)** 우선 — 백테스트가 메이커 0.02%/레그로 검증됐다. 테이커 0.06%여도 +EV는 유지되지만(F1f 검증) 수익률은 하락한다.

### 집행 시 반드시 지킬 것
1. **두 레그가 모두 체결되기 전까지 포지션은 열린 것이 아니다.** 한쪽만 체결된 상태는 델타중립이 아니라 **방향성 베팅**이며, 이 전략의 전제가 무너진 상태다.
2. 퍼프는 **1x 격리마진**. 레버리지를 올리지 않는다 — wave4가 24조합(1~10x)을 실측해 **1x만 통과**했고, ASYM 10x는 MDD를 1.8%→41%로 23배 키웠다.
3. 페어를 늘리지 않는다 — wave14 실측: 1쌍 15.29% → 3쌍 11.58% → 10쌍 4.60%. 캐리 기회는 소수 극단 종목에 집중돼 있어 페어를 늘리면 약한 기회로 자본이 희석된다.

### 청산 조건
7일 평균 펀딩 APR이 **7.5% 아래로 떨어지면** 양 레그 동시 청산.

## 6. 알려진 한계 (숨기지 않음)

1. **데이터원 불일치**: 백테스트는 **Binance** 펀딩으로 검증됐고 이 신호 도구는 **Bitget** 펀딩으로 계산한다. 이 환경에서 Binance는 HTTP 451(지역차단)이라 선택지가 없었다. wave14는 Binance↔Bybit 부호일치 98.9%·OKX 91.7%를 실측했으나 **Bitget은 측정되지 않았다** — 정량화되지 않은 베이시스 차이가 존재한다.
2. **기존 paper 트래커(`research/paper/track.py`)는 현재 죽어 있다** — 같은 451 차단으로 `collect_live_snapshot()`이 예외를 던져 원장 대신 실패 상태를 쓴다. 이 카드의 도구는 그 대체가 아니라 **캐리 계열 한 개만 보는 최소 대안**이다. 트래커 전체를 Bitget으로 이관하는 것은 별도 작업으로 남아 있다.
3. **스캔 범위 80종목** (공개 API 요청량 제한). L4의 top200 전체가 아니다 — 다만 캐리 기회는 거래대금 상위에 대부분 포함된다(wave14).
4. **백데이터가 보증하지 못하는 것**: 미래 펀딩 레짐의 재현, 거래소 커스터디 리스크, 극단 이벤트의 베이시스 폭주. 이 셋은 사이징 상한과 회로차단기로 관리할 뿐 제거 불가다.
5. **$100에서 기대 수익액은 작다** — 연 10.27%는 약 **$10/년**이다. 이 전략의 유일한 레버는 자본 규모이고(wave14: 자본을 키우면 수익*률*이 아니라 수익*액*이 는다), 레버리지로 짜내려는 시도는 wave4·9·30·31·32가 전부 자본파괴로 실측했다.
